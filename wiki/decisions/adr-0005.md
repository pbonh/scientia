# ADR-0005: Lay out produced changes under a flat proposals/<change-id>/ tree

**Status:** accepted

## Y-Statement

In the context of a portable pipeline that produces changes on disk, facing the
OpenSpec-shaped vs flat-layout choice, we decided for the brief's
`proposals/<change-id>/` tree centralized in `kg_pipeline.paths` and against
reproducing OpenSpec's directory contract or a pluggable layout, to achieve
portability (ASR-1) and one layout authority, accepting divergence from
scientia's own self-hosting layout. Resolves proposal Open Question #3.
