# ADR-0004: Store the effective score as a derived, recompute-owned value

**Status:** proposed

## Y-Statement

In the context of the per-claim confidence model (ADR-0003) whose `effective`
value is read often, facing the drift-vs-cost tension of a persisted derived
value, we decided for storing `effective` but making `recompute` its sole,
idempotent writer (rollups read post-recompute values; freshness via
`recompute_all` + audit staleness) and against never-store or unguarded-store,
to achieve idempotent determinism (ASR-2) and a stable gate (ASR-4), accepting
a staleness window between input change and recompute.
